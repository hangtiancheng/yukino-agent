# Yukino Agent

AI intelligent OnCall assistant. Two product surfaces share one Next.js 16 + AI SDK stack:

- **OnCall** (`/`) — RAG chat over the ops knowledge base (Milvus dense+BM25 hybrid search, optional rerank) with LLM-generated A2UI interactive surfaces; knowledge docs upload via `POST /api/upload` (`.txt/.md/.markdown/.pdf/.docx` — PDF/DOCX text extraction via unpdf/mammoth with the legacy caps in `lib/ai/doc-extract.ts`; saved into `FILE_DIR`, indexed immediately); a LangGraph Plan-Execute-Replan AI Ops pipeline that turns Prometheus alerts into runbook-grounded reports (runbooks resolved by alert name; finished reports are written back into the KB as diagnostic-case docs); MCP log tools; a read-only `postgres_query` tool; and first-party Prometheus self-monitoring fed by yukino-sentry browser reports. The `/knowledge` page manages the KB (list / chunk preview / re-index / delete behind `ONCALL_ADMIN_TOKEN`); the bottom-right ops panel carries Active alerts (multi-source, one-click targeted diagnosis with live SSE progress), AI Ops run history and the diagnostic case library (`/api/diagnostic_cases`); user feedback (thumbs + reason/comment/correction on assistant answers, `UserFeedback` table via `/api/feedback`, anchored on `sessionId:messageIndex`) and the admin settings dialog (`components/oncall-settings.tsx`: chat prompts / skills / MCP connections management — ALL prompt+skill+MCP mutations are `ONCALL_ADMIN_TOKEN`-gated fail-closed) hang off the chat page; chat references carry per-stage retrieval ranks (vector/BM25/rerank, computed in `lib/milvus/retriever.ts`); operational probes live at `GET /api/ready` and `GET /api/config_check`.
- **DevFlow** (`/devflow`) — GitHub engineering copilot: syncs repos / issues / PRs / CI runs into PostgreSQL, runs deterministic-first AI analysis agents, keeps a per-repo RAG knowledge base (structure-aware chunking, GitHub content index, retrieval settings/tests), offers a conversation-backed chat with memory sealing/thread memory/candidate approval and a drafts-only write safety gate, exposes a read-only code workspace plus a code graph and knowledge graph, multi-agent workflow orchestration, multi-repo workspaces and cross-repo reports.

Both surfaces are public (no login).

## Tech stack

- Next.js 16 App Router + React 19 + TypeScript
- Vercel AI SDK v7 (`ai`): streamText / generateText (structured output via `output: Output.object({schema})`, result on `.output` — `generateObject` is deprecated) / tool / embed / embedMany
- LLM: OpenAI-compatible via `@ai-sdk/openai` createOpenAI
- Embedding: text-embedding-v4 via `@ai-sdk/openai-compatible`; `EMBEDDING_PROVIDER` ("openai" only); batches capped at 10 inputs
- Vector DB: Milvus Standalone (`@zilliz/milvus2-sdk-node`, gRPC :19530) in `lib/milvus/`. One collection (`MILVUS_COLLECTION`, default `yukino_knowledge`) carries both a dense FloatVector path (AUTOINDEX + COSINE) and a native BM25 full-text path (analyzer-enabled `content` field feeds a BM25 Function that populates `sparse`). `retrieve()` fuses dense+BM25 with RRF inside Milvus; `retrieveDense()` is COSINE-only — use it when an absolute score threshold matters (RRF scores are rank-based). When `RERANK_API_KEY` is set, `retrieve()` over-fetches fused candidates (up to 20) and reranks them through the Aliyun DashScope text-rerank endpoint (`lib/ai/rerank.ts`, qwen3-vl-rerank; failures degrade to fusion order) before cutting to topK (default 5). Unfiltered `retrieve()` calls are the OnCall view of the shared collection and drop `devflow:*` sources after fusion, so DevFlow chunks never leak into OnCall answers — scoped callers pass an explicit `filter` instead. Dim is inferred from the first embedding and the collection is auto-recreated on mismatch. Chunk `metadata._source` is promoted to a scalar `source` field for filtered search/delete. DevFlow retrieval goes through `scopedRetrieve()` (`lib/devflow/search.ts`): over-fetch → fingerprint+Jaccard near-duplicate removal → ≤2 chunks per parent → rerank (DashScope API when `RERANK_API_KEY` is set, otherwise the ported heuristic reranker in `lib/devflow/retrieval-post.ts`) → topK → sibling expansion via `metadata.sibling_ids`. DevFlow chunks are produced by the structure-aware chunker (`lib/devflow/chunking.ts`, port of the Python `structure_aware_v1`: markdown sections/fences, CSV header-aware rows, JSON key paths, code symbol regions, stable sha256 chunk/parent ids). Verify with `npx tsx tests/milvus.smoke.ts` (needs a valid embedding key) and offline chunking semantics via `npx tsx tests/chunking.smoke.ts`.
- Database: PostgreSQL via Prisma 7 (`prisma/`, `prisma-client` generator → `generated/prisma`, `@prisma/adapter-pg`). Singleton in `lib/db.ts` (cached on `globalThis`). `pnpm db:push`; `pnpm db:generate` after schema edits. The public `postgres_query` tool uses a separate restricted `ONCALL_DATABASE_URL` via `lib/ai/tools/postgres.ts` (the DSN is NOT a tool parameter): it must not reuse the app database or role and rejects administrative roles; without it the tool is unavailable while OnCall stays public. Host port defaults to 5432 to avoid a native PostgreSQL on 5432.
- MCP: `@modelcontextprotocol/sdk`. The built-in log source is `MCP_URL` (+ optional `MCP_TOKEN`); administrators can add multi-connections (`McpConnection` table, SSE or Streamable HTTP, per-connection headers) via `/api/mcp_connections` (CRUD + `:check` probe). `getLogMcpTools()` (`lib/ai/tools/query-log.ts`) merges all enabled connections and renames duplicate tool names `<connection>__<tool>`. Writes require `ONCALL_ADMIN_TOKEN` (fail-closed when unset — the surface is public); header values are never echoed back.
- Monitoring: `prom-client` registry in `lib/metrics.ts`, fed by `POST /api/log`, exposed at `GET /api/metrics`. Covers every yukino-sentry report type except ScreenRecord plus the Node/V8 metrics prom-client omits (heap limit, heap-used ratio, detached contexts, array buffers, event loop utilization, page faults). Browser-supplied label values are capped at 50 distinct values (overflow → `other`). The registry is cached on `globalThis`: when the metric set changes you MUST bump `METRICS_VERSION`, or a long-lived dev server serves a cache whose new fields are `undefined` (typed as present, so tsc cannot catch it) and every `.inc()` throws TypeError. Alert rules live in `prometheus.rules.yml`; every alert name MUST have a matching heading in `data/docs/alert-handling-guide.md` (AI Ops resolves runbooks by alert name). Operational probes: `GET /api/ready` (database / Milvus / LLM+embedding+rerank config presence / Prometheus / MCP reachability; 503 when core deps are down) and `GET /api/config_check` (expectation checklist with non-sensitive summaries, never echoing key values). The Go bridge (`yukino.go/yukino_agent/internal/app/sentry_metrics_handler.go`) exposes byte-identical `yukino_sentry_*` names so one Prometheus and one rule file serve both jobs — change both together. Verify with `npx tsx tests/metrics.smoke.ts`.
- Startup: `instrumentation.ts` register() starts Langfuse observability (no-op when unconfigured), then embeds every doc in `FILE_DIR` (./data/docs) into Milvus
- AI Ops: Plan-Execute-Replan is a LangGraph StateGraph in `lib/ai/pipelines/plan-execute-replan/graph.ts` — planner → executor (one plan step per node run) → replanner loop, exiting to uiify (optional A2UI surface) or exhausted. Nodes publish `PlanExecuteEvent` payloads to the "custom" stream via `getWriter()` — NOT the `writer()` helper, which in langgraph 1.4.x reads `configurable.writer` (no longer populated by Pregel) and silently drops every event; `index.ts` re-validates every chunk against the zod schema in `events.ts` before yielding. The replanner `iteration` budget (`MAX_ITERATIONS`) is the real loop guard; `RECURSION_LIMIT` is a safety net only — keep them in sync. Graph state uses `Annotation.Root` because this repo's zod is v4 (`zod/v4`) and its `~standard` lacks the JSON-Schema props langgraph's `StateSchema` demands. `/api/ai_ops` persists the finished report as a diagnostic-case markdown doc in `FILE_DIR` (`diagnostic-cases.ts`: sha256-hash filename dedup, 200-file cap for the public endpoint, fire-and-forget — persistence failure never discards the report). `POST /api/ai_ops` accepts an optional `{query?, alert?}` body (alert-driven targeted diagnosis, legacy AiopsRunForm) and records an `AiOpsRun` row for history (`GET /api/ai_ops/runs`); `POST /api/ai_ops/stream` streams the same run as SSE `PlanExecuteEvent` frames (`run_started`/`plan_created`/`step_start`/`step_done`/`replan`/`done`/`error`, client parser in `hooks/aiops-stream.ts`) so the chat message and the alerts panel show a live step timeline — run persistence is shared via `lib/ai/aiops-run.ts`; `GET /api/active_alerts` + `components/active-alerts-panel.tsx` expose the live alert list with one-click diagnose. Alerts aggregate from multiple sources (`ALERT_SOURCES` JSON: Prometheus v1 + Alertmanager v2, basic auth, per-source failure tolerance, same-name dedup — `lib/ai/alerts.ts`) and carry the full legacy ActiveAlert fields (service/severity/labels/annotations/context_url/fingerprint). Guardrails ported from legacy: plan steps referencing undiscovered tools are marked skipped, and the final report is template-validated with a deterministic fallback. Verify with `npx tsx tests/ai-ops-graph.smoke.ts` (live: `AI_OPS_SMOKE_LIVE=1`) and `npx tsx tests/oncall-ops.smoke.ts`.
- Tool-call audits: every chat AND AI Ops tool call is recorded fire-and-forget into the `ToolCallAudit` table (session/turn/tool/source builtin|mcp/truncated input+result/status/duration; shared writer in `lib/ai/tool-audit.ts`) and readable via `GET /api/tool_audits?session=` — AI Ops runs audit under session `aiops:<runId>` (legacy `aiops_tool_call_audits`). `AiOpsRun.events` also persists a truncated PlanExecuteEvent timeline (plan/step_start/step_done/replan, the lightweight successor of the legacy evidence-chain tables) rendered in the ops panel run history.
- Observability: Langfuse in `lib/observability.ts` — OTEL `NodeSDK` + `LangfuseSpanProcessor` started from `instrumentation.ts`, one `CallbackHandler` trace per graph run (graph/node spans), `observeGeneration()` records each AI SDK call as a generation, `withAiOpsTrace()` propagates session/tags. Enabled only when LANGFUSE_PUBLIC_KEY + LANGFUSE_SECRET_KEY + LANGFUSE_BASE_URL are ALL set; every hook degrades to a no-op otherwise.
- Frontend: Tailwind v4 atomic classes + streamdown (streaming markdown + Shiki highlighting)
- i18n: `next-intl` v4 with NO `[locale]` segment — `i18n/request.ts` resolves the locale per request (cookie `yukino_locale` → `Accept-Language` negotiation in `lib/i18n/negotiate.ts`), so the first server-rendered byte is already localized and hydration never mismatches; the same request config feeds `formats` from `lib/i18n/formats.ts` (typed via `AppConfig.Formats`), and `getTranslations` also works inside Route Handlers. Catalogs: `messages/en.json` (source of truth) + `messages/zh-CN.json`; keys are compile-time checked via the `AppConfig` augmentation in `types/next-intl.d.ts` (an unknown key fails `pnpm typecheck`). ICU syntax available; switching = `persistLocale()` (`lib/i18n/client.ts` writes the cookie) + `router.refresh()`, mounted as the `LanguageSwitcher` dropdown floating top-right on the OnCall page and in the DevFlow header. Translated: every product surface — OnCall chat (incl. `use-chat.ts`), dock, gallery, both workspace shells, ALL DevFlow pages (incl. the `badges.tsx` status labels and `analysis-views.tsx`), and all `generateMetadata`; dates go through `useFormatter()` (`format.dateTime(date, "short" | "medium" | "date")`) instead of `toLocaleString`. Dynamic enum values (GitHub states, conclusions…) map value→key via `as const`/`Record` tables and render `t(\`group.${MAP[v]}\`)`with a raw-string fallback. **API responses are localized too**: the `api.devflow`/`api.oncall`namespaces carry the`{message,data}`envelope text — devflow`fail(status, key, args?)`is key-typed with`failRaw()`as the explicit escape hatch for dynamic diagnostics (exception / GitHub API text passes through untranslated), and OnCall routes translate inline with`getTranslations`. ## Coding conventions

- Styles use only Tailwind v4 atomic classes; do not create custom CSS classes (no styles.css).
- Tool definitions follow a three-layer split: `lib/ai/tools/schemas.ts` (zod) → `operations.ts` (pure functions) → `index.ts` (AI SDK `tool` wrapper).
- API responses are wrapped as `{ message, data }`.
- Configuration is read via `.env` + `lib/config.ts`; no yaml.
- Strict typing: validate runtime-unknown data with zod (`safeParse`/`parse`); no unnecessary type assertions, no `@ts-ignore` / `eslint-disable`.

## DevFlow workspace (GitHub engineering copilot)

At `/devflow` (UI) and `/api/devflow/*` (REST). Connects GitHub repositories, syncs issues / pull requests / CI runs into PostgreSQL, runs AI analysis agents, and keeps a per-repo RAG knowledge base in Milvus.

- **Data flow**: `POST /api/devflow/repos` verifies the repo via the GitHub API (or attaches a `localPath` checkout / honors `cloneParentDir`, legacy connect modes), encrypts the optional token (AES-256-GCM, `crypto.ts`), then `sync.ts` upserts issues, PRs (+ files + review comments) and workflow runs (+ jobs; failed runs also fetch per-job logs, secret-sanitized via `sanitize.ts` — port of the Python `sanitize_ci_log` — then head+tail truncated before storage). Everything is keyed by GitHub id (`repoId_githubIssueId` etc.).
- **Analysis agents** (`agents/analysis.ts`): Issue Triage / PR Review / CI Debug each assemble a bounded context and are deterministic-first — a rule engine always computes the baseline (category/priority/complexity tables, CI failure-type classifier, PR blocking downgrade, owner allow-list validation); LLM output is merged on top of it, total LLM failure persists the deterministic result with `generationMode: "deterministic"` (never a 500); results persist an `AnalysisResult` row. `generateStructured()` retries once with a stricter "JSON only" reminder when the first response fails schema validation (some OpenAI-compatible gateways wrap JSON in prose). Prompts in `agents/prompts.ts`; output schemas in `schemas.ts`.
- **Safety gate**: agents never write to GitHub. They create `ActionDraft` rows (`pending_confirmation`); only `PATCH /api/devflow/drafts/:id {action:"execute"}` performs the real API call (`drafts.ts`). The UI requires an explicit confirm dialog.
- **Per-repo RAG** (`rag.ts`): documents are SHA-256-deduped, structure-aware-chunked, embedded and stored in the shared Milvus collection with `source = "devflow:kb:<repoId>:<docId>"`, so retrieval is scoped to one repo via a `source like` filter. `askKnowledge()` does evidence-grounded QA with numbered citations and refuses to fabricate — an answer gate (port of the Python `answer_gate`) refuses when NONE of the question's strong signals (identifiers, `#123` refs, long numbers) appear in the evidence and asks for clarification on ambiguous demonstrative queries. Weekly reports (`agents/report.ts`) land here too; KB-indexing failure never discards a generated report. The KB accepts text/markdown/code/JSON/CSV/log/YAML/XML/HTML (`TEXT_EXTENSIONS` in `rag.ts`) plus PDF/DOCX (`extractText` → `lib/ai/doc-extract.ts`). Document-level RAG-studio surfaces: chunk preview (`GET /api/devflow/knowledge/:docId/chunks`, reads the exact indexed rows via a scalar-filter Milvus query), retry of a FAILED document (`POST /api/devflow/knowledge/:docId/retry` — the raw text is persisted in the `KnowledgeDocumentBody` 1:1 side table), direct memory-note creation (`POST /api/devflow/knowledge/notes` → `memory_note` doc), and repo RAG status (`GET /api/devflow/knowledge/status`).
- **Skills** (`lib/devflow/skills.ts` + `data/devflow-skills/*/SKILL.md`): six SKILL.md engineering playbooks (issue-triage, pr-review, ci-debug, weekly-report, safety-draft, project-investigation) with YAML-frontmatter manifests. The chat agent always carries the skill catalog in its system prompt and injects the full workflow instructions of the skills whose triggers match the message (explicit request by name wins); activation is trigger-scored (ASCII word-boundary + CJK substring), resources referenced as `references|templates|scripts|assets/...` are loaded path-guarded. `GET /api/devflow/skills(+/:name)` list/inspect. Divergences: `entrypoint` is metadata-only (AI SDK tools replace the legacy per-skill dispatch; tool allow-list is advisory) and the legacy stdio MCP-status probe is not ported (in-process tools).
- **Chat agent** (`agents/chat.ts`): resilience ports from legacy — duplicate identical tool calls are circuit-broken after 2, tool errors are classified into 8 kinds with one auto-retry for timeout/network/rate-limit classes, context-overflow retries with a reduced history window, empty answers fall back to an honest tool-trace summary, and failed turns are persisted as assistant messages so feedback stays anchored. `streamText` with repo-scoped tools (list/get issues & PRs, CI runs/logs, knowledge search, `create_action_draft`, the memory tools (`memory_recall` / `memory_propose` / `search_evidence` / `read_conversation_transcript`), plus the legacy agent-trigger tools `analyze_issue` / `analyze_pull` / `analyze_ci_run` (run the full analysis agents and persist an `AnalysisResult`), `generate_weekly_report` and `repo_health`). `/api/devflow/chat` streams SSE (`connected`/`message`/`tool`/`done`/`error`), same framing as `/api/chat_stream`. Chats are conversation-backed: the request is `{repoId, conversationId?, message}`, the server resolves/creates the conversation, persists the user message, streams, then persists the assistant message (with its tool trace); `done` returns `{conversationId, userMessageId, assistantMessageId}` so the client can anchor feedback. Model history is the last 30 persisted messages (not client-supplied), compressed into a token budget by the progressive context compaction port (`lib/devflow/context-compression.ts`, legacy `context_compression.py` + `ProgressiveContextManager`): per-turn pressure staging (normal/warning/auto_compact/aggressive/manual_path over an estimated-token window), `compressMessages` budget windowing with per-message clipping, and — past the auto-compact threshold — LLM summarization of the older segment into a persisted `compact_boundary` system message (session-memory mode when a `ConversationMemory` snapshot exists, deterministic extractive fallback on an empty reply, key-fact preservation appendix, 3-failure circuit breaker). The boundary summary is injected into the system prompt as a `[Compaction Boundary]` section; system rows never reach the UI timeline (the messages route filters to user/assistant) and never count toward sealing.
- **Conversations & feedback**: `lib/devflow/conversations.ts` (per-repo `Conversation` + `ChatMessage`; soft-delete cascades messages/feedback and returns a replacement; the first user message renames a default-titled conversation) and `lib/devflow/feedback.ts` (helpful/unhelpful on an assistant message, upsert-by-message, metrics, a review workflow, an evidence `trace`, optional Feishu/Lark notification for negative feedback — `notificationStatus="not_configured"` when `DEVFLOW_FEISHU_WEBHOOK_URL` is empty). Feedback is anchored on the assistant `ChatMessage` id. UI: the Agent Chat page has a conversation sidebar + inline thumbs; `/devflow/feedback` shows metrics + a review queue with trace/review dialogs.
- **Webhooks & scheduler**: `app/api/devflow/webhooks/github` (HMAC-SHA256 verified against `GITHUB_WEBHOOK_SECRET`, schedules a background re-sync); `lib/devflow/scheduler.ts` (in-process periodic re-sync from `instrumentation.ts`, no-op unless `DEVFLOW_AUTO_SYNC_ENABLED=true`; recursive `.unref()`ed `setTimeout` — only meaningful on a long-lived Node server).
- **Permissions**: `lib/devflow/permissions.ts` (`ensureDemoUser` single-tenant owner, role→permission map, `requirePermission`, `writeAuditLog`). The draft approve/reject path is gated by `draft:approve` and writes an `AuditLog` row.
- **Frontend**: `app/devflow/layout.tsx` wraps a `ThemeProvider` + `DevflowProvider` (repo context, `components/devflow/provider.tsx`) + sidebar shell. All pages are client components built from `components/ui/*`. Because the React Compiler `react-hooks/set-state-in-effect` rule flags any effect that transitively calls setState (even after `await`), data fetching lives in **inline async IIFEs inside the effect** and manual reloads bump a `reloadKey` state — do NOT call a `useCallback` loader from an effect.
- **GitHub content index**: `POST /api/devflow/content-index` chunks + embeds a repo's synced issues, PRs and sanitized failed-CI logs into Milvus (`source = devflow:item:<repoId>:<type>:<id>`, `lib/devflow/content-index.ts`, port of the legacy source_policy RAG sources), powering `GET /api/devflow/issues/:id/similar` (semantic near-duplicates) and chat-side recall. `POST /api/devflow/pulls/:id/review-checklist` generates a deterministic (no-LLM) pre-merge checklist from files/CI/review state.
- **KB configuration + retrieval tests**: per-repo `KnowledgeBaseConfig` (retrieval method hybrid/dense/bm25, rerank toggle, topK, score threshold, chunk size/overlap — honored live by `scopedRetrieve`) via `GET/PUT /api/devflow/knowledge/config`; the legacy `score_threshold` stage is ported as `applyScoreThreshold()` in `rag.ts` — because fusion/rerank scores are rank-based, the absolute gate is evaluated against dense COSINE similarity (default OFF, threshold 0.5) and applied in both `searchKnowledge` and retrieval tests; `POST/GET /api/devflow/knowledge/retrieval-tests` persist and replay retrieval runs (`RetrievalTestRun`). `askKnowledge` degrades to an extractive (no-LLM) answer with `generationMode: "extractive"` when the model call fails.
- **Memory system** (`lib/devflow/memory.ts`): conversation sealing — after ≥8 new messages a conversation is distilled into a `ConversationMemory` snapshot (LLM structured summary with deterministic fallback when no key), thread memories merge into `ThreadMemory` (counts-based, idempotent), memory candidates (`MemoryCandidate`) proposed by sealing or the `memory_propose` chat tool become KB `memory_note` docs on approval (`/api/devflow/repos/:id/memory-candidates` PATCH approve/reject; KB-index failure never blocks approval). `buildMemoryContext` injects thread summary + decisions/open questions/tasks into the chat system prompt; `memory_recall` tool returns the same text. Recall auditing is ported from the legacy memory_hub: `recordRecallEvent` persists a `RecallEvent` row (fire-and-forget) from the `memory_recall` / `search_evidence` / `read_conversation_transcript` chat tools and from `GET /api/devflow/repos/:id/memory/search` — the cross-scope evidence search (KB docs + GitHub content index via two `scopedRetrieve` calls, merged by score) that backs both the memory panel's search box and the `search_evidence` chat tool (legacy `devflow_search_evidence`); `read_conversation_transcript` is the legacy `devflow_get_thread_context` port (verbatim user/assistant transcript with keyword filter + backwards paging, reaching past the 30-message model window); `GET /api/devflow/repos/:id/memory/recall-events` lists the audit trail (rendered in the chat page memory panel). Chat answers surface `citations` (knowledge hits collected from retrieval tools, persisted in message meta + streamed in the `done` frame). Chat page renders the Memory panel (thread snapshot + pending candidates with approve/reject).
- **Workflow orchestration** (`lib/devflow/agents/workflow.ts`, legacy Planner/Observer/Synthesis): `POST /api/devflow/chat/plan` plans bounded claims over synced entities (LLM + deterministic fallback; claims outside the repo's data are rejected), `POST /api/devflow/chat/plan/execute` streams task execution as SSE (same-entity serial, cross-entity parallel ≤3, 90 s per-task timeout, ≤2 replans), observer findings (blocker/warning + confidence synthesis) and a decision memo persist into `AgentWorkflowRun`/`AgentTaskRun`; safety invariant kept structurally — workflow tasks are read-only, GitHub writes still only happen through confirmed `ActionDraft`s. UI: `/devflow/workflow-runs`.
- **Code graph** (`lib/devflow/code-graph.ts`): regex symbol/relation extraction over the managed checkout (imports/calls/defines; TS/JS/Py/Go/Rust/Java/SQL/shell symbol families) into `CodeSymbol`/`CodeRelation` rows; `POST /api/devflow/repos/:id/code-graph` rebuild, GET symbol search, `impact` returns one-hop dependents for changed files; PR review + CI debug contexts receive the impact summary (honest null until a rebuild ran). UI: `/devflow/code-graph`. PR worktree snapshots are intentionally NOT migrated (read-only managed-clone design).
- **Knowledge graph** (`lib/devflow/knowledge-graph.ts`): relation edges derived from synced data — #N references, closing-keyword resolves, assignees/authors, weekly-report documents, conversation decides — into `KnowledgeGraphEdge`; rebuild fires after every sync; `subgraph` endpoint does BFS ≤2 hops / 72-node cap; UI `/devflow/graph` renders a static layered SVG + adjacency list.
- **Workspaces** (`lib/devflow/workspaces.ts`): multi-repo groupings (`Workspace`), aggregated stats (prisma groupBy) and a cross-repository report (deterministic risk grading P0/P1/P2 + LLM narrative with template fallback; per-repo weekly reports saved into the KB fire-and-forget). Routes `/api/devflow/workspaces*`, UI `/devflow/workspaces`.
- **Analyze streaming**: `POST /api/devflow/{issues,pulls,runs}/:id/analyze/stream` (debug for runs) streams coarse-grained trace frames (context/rules/llm/merge) then the full analysis result; legacy's thinking_delta second-LLM stream is NOT ported (documented in code).
- **Team + recommendations**: `TeamMember` rows per repo (`/api/devflow/repos/:id/team-members`) feed the Issue analysis owner allow-list (assignees ∪ team ∪ authors); `GET /api/devflow/repos/:id/recommendations` returns context-aware suggested questions (pure-rule port of the legacy RecommendationAgent, localized via the `devflow.recommendations` namespace) shown as chat empty-state chips.
- **Code workspace**: `lib/devflow/workspace.ts` manages a server-side shallow git clone per repo (`git clone --depth 1`, or `fetch` + `pull --ff-only` to refresh, via `execFile` with an argv array — no shell, so repo/branch/token cannot inject commands) under `config.devflow.workspace.checkoutDir` (default `./data/workspaces/<repoId>-<owner>__<name>`). That directory is git-ignored and excluded from tsconfig/eslint — cloned third-party code is data, not our source. It exposes path-guarded read-only file tools (`listFiles`, `readCodeFile`, `searchCode` — a scored lexical scan) that refuse path traversal, VCS/build dirs, binaries and secret files (`.env`, `.npmrc`, ...). `lib/devflow/project-index.ts` discovers the repo's docs/manifests (README, package.json, docs/, CI config), chunks + embeds them into Milvus with `source = "devflow:project:<repoId>:<docHash>"`, and tracks a per-repo `ProjectIndex` row (status / fingerprint / summary / staleness). Wired into the chat agent as `workspace_list_files` / `workspace_read_file` / `workspace_search_code` / `search_project_docs`, surfaced in `/devflow/code` (clone/refresh, browse, search, index), exposed via `/api/devflow/repos/:id/workspace*` + `/project-index`. Requires `git` on PATH; project-doc embedding needs a valid embedding key. Verify discovery/classification/chunking without embeddings via `npx tsx tests/devflow-b.smoke.ts`; offline suites: `tests/chunking.smoke.ts`, `tests/doc-extract.smoke.ts`, `tests/devflow-defects.smoke.ts`, `tests/devflow-chat-resilience.smoke.ts`, `tests/devflow-analysis.smoke.ts`, `tests/devflow-content-index.smoke.ts`, `tests/oncall-chat-protocol.smoke.ts`, `tests/oncall-ops.smoke.ts`.

## A2UI integration (v0.9)

- The LLM optionally appends ONE `<a2ui-json>[...]</a2ui-json>` block (JSON array of A2UI v0.9 messages) after a markdown summary; the prompt section + OnCall few-shot builders live in `lib/ai/a2ui/prompt.ts` (change UI examples there, the prompt updates itself).
- `lib/ai/a2ui/extract.ts`: `createA2uiStreamFilter()` strips blocks from the text stream (holds back partial-tag tails across chunks); validation is `A2uiMessageListSchema.safeParse` from `@a2ui/web_core/v0_9` only — do not reintroduce hand-rolled checks.
- **zod red line**: web_core bundles its own zod v3; never compose its schemas into app `zod/v4` combinators — app boundaries carry `unknown[]`, per-payload validation calls the web_core schema directly.
- `chatStream()` yields `ChatStreamEvent` (`text` / `a2ui` / `notice` / `references` / `reasoning` / `tool`); SSE emits them as `message` / `a2ui` / `references` / `reasoning` / `tool` — `reasoning` carries model thinking deltas (Anthropic thinking plumbing) and `tool` carries live tool-call progress (call/result/error), both rendered by `msg-list.tsx`. The `references` event carries the knowledge-base sources grounding the turn (title/source/score/excerpt/knowledgeType) and renders as citation chips under the reply — emitted before the first text chunk. `knowledgeType` (`sop` / `document` / `diagnostic-case`) is classified at index time (frontmatter `knowledgeType:`, `aiops-case-` prefix, sop filename/body heuristics — `knowledge-index.ts`) and labels the chips. `chat()` returns `{ answer, a2ui?, references? }` and `/api/chat` puts them in `data.a2ui` / `data.references`. Invalid blocks get exactly one no-tools corrective retry (`lib/ai/a2ui/correct.ts`, model is a parameter), then degrade to an honest notice — never fabricate UI data. Memory keeps the raw tagged text so follow-up actions have context; pairs sliding out of the fixed window are folded into an LLM rolling summary (≤1200 chars, `MEMORY_SUMMARY_ENABLED`, injected as a `## Conversation summary` system section) instead of being dropped (legacy compaction, minimal port).
- AI Ops: after the replanner finishes, a "UI-ify" pass (`uiifyReport` in `graph.ts`, think model, no tools) optionally renders the report as a surface; `/api/ai_ops` returns it in `data.a2ui`. Its failure never discards the report.
- Client: `ChatMessage.a2ui?: unknown[]` (persisted in localStorage histories); `components/a2ui-view.tsx` owns a per-message `MessageProcessor([shadcnCatalog])` (surfaceIds isolated per message; cross-message deleteSurface unsupported), validates each message with `A2uiMessageSchema.safeParse`, renders `<A2uiSurface>` under `MarkdownContext.Provider`.
- Surface actions are serialized as `[UI_ACTION] <name>\ncontext: <json>` and auto-sent through the normal chat send path.
- `reactStrictMode` is off: the MessageProcessor is a stateful external store and StrictMode's dev double-effect replays surfaces on re-subscription.
- `catalog/` (18 basic + 47 shadcn extension components) and `components/ui/` are ported from the a2ui repo — keep edits minimal.
- Verification: `/gallery` renders every extension component backend-free; `npx tsx tests/a2ui.smoke.ts` checks prompt examples, stream-filter chunk-splits, and validation semantics.
